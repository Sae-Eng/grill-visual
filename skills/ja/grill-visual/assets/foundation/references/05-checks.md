# 05 確かめ方

作ったあとに壊れを止める。物差しは毎回、採点は要るときだけ。

| 段 | だれが | いつ | 何をする |
|---|---|---|---|
| 1 物差し | 機械 | 毎回 | `html-check` を回し、✗ を 0 にする。! は読んで、直すか決める |
| 2 ブラウザで見る | 作った AI | 毎回 | 内部ブラウザで代表の1画面を開き、図・文字・リンク・折りたたみ・切り替えを見る |
| 3 採点 | 作った AI とは別の AI(1人・1回) | 人に出す資料と、頼まれたとき | 下の採点表で見る。否を作った AI が直して終わる |

## 1 物差し html-check

```sh
node <このスキル>/scripts/html-check.mjs <HTML のパスか URL> [--prep <JS>] [--dark] [--shots <dir>] [--config <JSON>] [--json]
```

- Node 22 以上。Chromium は Playwright の置き場か Chrome を探す。無ければ `npx playwright install chromium-headless-shell` を1回流すか、`HTML_CHECK_CHROME` で渡す。
- 終了コード: 0 = ✗ なし、1 = ✗ あり、2 = 動かせなかった。
- 狭い幅(680px)で文字と図を、広い幅(1280px)で1行の字数を測る。

| 項目 | 既定の線 | 結果 | 設定のキー |
|---|---|---|---|
| 小さすぎる文字 | ページの文字と、表示した図の文字が 11px 以上 | ✗ 止める | `minText` |
| 図の文字の重なり | 重ならない | ✗ 止める | — |
| 横のはみ出し | ページが横にはみ出さない。図の文字が図の外へ出ない | ✗ 止める | — |
| 図の色 | 1枚に4色まで | ✗ 止める | `maxColors` |
| 本文の大きさ | 14〜15.5px | ! 知らせる | `bodyMin` `bodyMax` |
| 行間 | 本文 1.7・ほか 1.5 以上 | ! 知らせる | `lineHeightBody` `lineHeightOther` |
| 1行の字数 | 40字以内 | ! 知らせる | `maxChars` |
| 矢印の札 | 矢印の近くに札がある | ! 知らせる | `arrowPad` |

- 線を変えるときは、変えるキーだけを書いた JSON を `--config` で渡す(例 `{"maxChars": 45}`)。理由をページか作り手のスキルに書く。
- 図の色の数え方: 地と文字の色・灰・白・黒は数えない。ページの地と明るさが近い色(差が 20% 未満)は地とみなす。色相と明るさがほぼ同じ色は1つにまとめる。幅 240px 未満の SVG は図として数えない(`picMinWidth`)。
- 閉じた `<details>` は開いてから測る。切り替えで隠れた図は測られないので、全部を並べる切り替えを `--prep` で押してから測る(例 `--prep "document.getElementById('all-btn').click()"`)。
- わざと線に届かない物(悪い例の小さな文字、操作の帯など)は、その要素に `data-check-skip` を付け、ページに理由を書く。
- ダークを持つページは `--dark` でも回す。


## 2 ブラウザで見る

- 内部ブラウザ(使っているツールの中のブラウザ)で開く。PC の代表の1画面を見る。
- 切り替え・ステップ再生があれば全部の案と全部のコマを見る。説明に書いた件数・並び・つながりと、実際の表示が合うかを見る。
- 狭い幅・ふつうの幅・広い幅の3つで崩れないかを見て、スクリーンショットで目立つ崩れから直す。
- 見るために押した選択や切り替えは、渡す前に再読み込みで消す。開いたタブは閉じる。


## 3 採点(人に出す資料と、頼まれたとき)

作った AI は採点を自分でしない。新しいコンテキストの AI を1人立て、次だけを渡す。
作った側の説明(どう工夫したか)は渡さない。読み手と同じ所から見てもらうため。

- 図の画像(`--shots <dir>` が狭い幅で撮った PNG)と、ページ全体の画像
- 図ごとの一言と、図の上の「絵の型」の1文
- この採点表と、返す形

### 図1枚ごとの7項目

| 項目 | 合の目安 | 否の例 |
|---|---|---|
| 一言が図から伝わる | 一言を読まずに図だけを見て、伝えたいことを1文で言える。最初に目が行く所が一言の主役 | 一言の主役に目が行かない |
| 主役は4つ前後 | 目が追う主役が4つ前後 | 5つ以上の話が並ぶ |
| 描き方は1種類 | 1枚の中で描き方(見立て・実物の画面・チャートなど)がそろう | 輪・梯子・帯が混ざる |
| 線・矢印・色の意味が分かる | 線と矢印に札がある。色の意味が札で分かる。4色まで | 名前の無い帯がある。色が多い |
| 番号と札が物に付く | 札が物の隣にある。番号が重ならない。要確認の札に中身が短く書いてある | 番号が重なる。札が番号だけ |
| 絵が主役になっている | 見立て・場面・実物の画面などの絵が主役 | 箱を矢印でつないだだけの図が主役 |
| 構造が分かる | 「絵の型」の1文どおりに、区画・流れの向き・段が図から読める。区画の名前が図の中にある | 区画の境が見えない |

- 機械が描く ER 図・状態図は「絵が主役」の対象外(合とする)。

### ページ全体の5項目

| 項目 | 合の目安 | 否の例 |
|---|---|---|
| 要点が先に分かる | 開いた最初の画面で、何の資料かと全体の図の上の方が見える | 説明の文が続き、図がスクロールの先にある |
| 迷わず移れる・探せる | 今いる所が分かり、押せば戻れる。押せる物に印があり、区画の始まりと終わりが分かる | 寄りの図から全体へ戻る道が無い |
| 操作にすぐ応える | 押すとすぐ移る。開いただけで動き続けない | 押せそうに見えて何も起きない物がある |
| だれでも・どの幅でも読める | 狭い幅では図を縮めずに横へ送る。状態を色だけで示さない | 狭い幅で図の文字が読めない |
| HTML ならではの見方がある | 押して潜る・切り替えて比べるなど、紙では見られない見方がある | 紙に刷っても同じ |

### 返す形

```json
{
  "pictures": [
    {"name": "全体の図", "one": "図に添えた一言",
     "items": [{"item": "一言が図から伝わる", "value": "合", "note": ""},
               {"item": "主役は4つ前後", "value": "否", "note": "どこが・どの決まりに当たるか・どう直すか"}]}
  ],
  "page": [{"item": "要点が先に分かる", "value": "合", "note": ""}],
  "result": "否を直す"
}
```

- `value` は 合・否・判断できず。`result` は、否が1つでもあれば「否を直す」、無ければ「合格」、判断できずがあれば「合格(判断できず N)」。
- 否を直し終えたら、作った AI が否の項目に `fix`(どう直したか)を足す。採点し直しはしない(頼まれたら回す)。
- 「判断できず」は理由を添えて、人に見せる。
