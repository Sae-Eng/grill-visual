# 01 好み・原則

どの HTML にも効く、抽象の決まり。読みやすいページのための好みと原則を置く。

## 資料は絵が主役

- 絵を主役にし、一言を添える。コード・表・長い説明は「詳しく」に畳む。
- 箱に文字を並べただけの図、矢印でつないだだけの図、コードの塊を主役にしない。
  場面(人が何かをしている絵)・実物の画面のモック・見立ての絵を先に考える。
- 1枚の描き方は1種類にそろえる。


## 見立ては使ってよいが、中身は実物と実名

- 見立て(道・門・遮断機・棚など)を主役にしてよい。その上に載る中身は、実物と実名にする。
  例: 道を進むのは PR のカード、門のランプは CI の ✓ ✗、行き先は main ブランチの線、表は DB ツール風の表のモックに列の実名。
- 中身までたとえ(単語帳＝辞書、封筒＝回答の行 など)にしない。かえって思い浮かべにくくなる。
- 寄りの絵は実物(PR の画面など)でもよい。どちらにするかは伝わりやすさで選ぶ。
- 実物の画面を作り物で描くときは「例」と書く。


## 絵は工程の粒度まで。全体図は区画で境界を見せる

- 箱を数個並べた概要で止めない。手順・人の確認点・担い手・成果物・戻りの流れまで、元資料の粒度で描く。
  画風を決めても、描く中身の細かさは別に詳しくする。
- 全体図(1枚)と寄りの図を分ける。全体図の主役は4つ前後にし、細かい手順は寄りの図か札へ回す。
- 全体図は区画ごとに名前を付け、境界を見せる。大事な区画は太枠にする。区画の地は背景の層に置く。
- 押すと開く札も、文の表にせず図にする。人が見る所は「どこからどこまで見るか」と、なぜ人が見るかまで描く。
- 元資料に手順表があれば、その番号と名前をそのまま図に写す。


## 項目は横一列に流さず、見出しの下に入れ子で並べる

- 種類の違う項目を横一列に詰めない。見出し → 中身の木(入れ子)にし、どこからどこまでが1つの項目かを見せる。
- 同じ種類の物を比べるときだけ、横に並べる。


## 表現の幅は狭めない。図は毎回発想する

- 見本や前の資料の図を写さない。論点ごとに表現を2〜3案考えてから選ぶ。同じページに同じ型の図を並べない。
- 決まりで縛るのは、見た目の既定(02)と壊れ(05)まで。何をどう描くかは毎回考える。
- HTML ならではの見方(押して潜る・切り替えて比べる・1コマずつ進める)を使う。紙に刷っても同じなら、HTML にした意味が薄い。


## 方向を1つ決めて徹底する

- AI に任せると、見た目は一番ありがちな形へ寄っていく。題材から方向を1つ決め(02)、書体・色・部品・図をその方向で通す。途中で混ぜない。


## 避ける組

- 紫〜青紫のグラデーション。
- 生成りの地に赤茶の強調(「the Claude look」と呼ばれる、紫の次によく出る定番)。
- 飾りだけの大きな番号(01 / 02 / 03)、意味の無い絵文字、枠とグラデーションと影の重ね。
- 色は題材から役割を決めて選ぶ。「上品な定番」から選ばない。
