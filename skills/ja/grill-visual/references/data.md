# 議論のデータ（page.json）

議論のフォルダに置く、問いと決定の正のデータ。`scripts/build.mjs` がこれと図の断片（`fig/`）から `index.html` を組み立てる。
discussion.md は人が読む記録として今までどおり書き、page.json と食い違わないようにする（版・ID・回答・決定）。
例は [../assets/page.example.json](../assets/page.example.json)（架空の議論「ToDo アプリに通知を付ける」の6問・6決定・終わったあと）。

```
artifacts/grill-visual/<topic>/
├── page.json        問い・決定・経緯（この文書）
├── fig/qNN.svg      問いごとの図の断片（メインが書く。.js でもよい）
├── discussion.md    記録
├── tasks.json       タスク（終わったら。下の「タスクのデータ」）
├── index.html       組み立てた議論ページ（手で直さない）
└── summary.html     組み立てたまとめ（手で直さない）
```

## ページ全体

| 項目 | 型 | 意味 |
|---|---|---|
| `version` | 数 | 版。discussion.md と同じ番号。回答を受けてページを直すたびに1つ上げる |
| `date` | 文字 | 版の日付（YYYY-MM-DD） |
| `round` | 数 | いまのラウンド。ヘッダーの「Nラウンド目」 |
| `status` | `open`・`ended` | `ended` で終わりの札を出す |
| `limits` | `{q, r}` | 上限。指定がなければ `null`。数があるときだけ「（上限 N）」を添える |
| `direction` | 文字 | 土台 02 の方向の組（`<html data-direction>`）。既定 `blueprint` |
| `title` | 文字 | 目的を1文（h1） |
| `lead` | 文字 | このラウンドで決めること |
| `intro` | 区画の配列 | 依存マップの前に置く区画（診断・測った結果・全体の備考への答えなど）。無ければ `[]` |
| `map` | 区画 | 論点の依存マップ。`nodes` から組み立てが札と線を描く（`figs` を書いたときだけ、その図を使う。下の「図の断片」） |
| `end` | 文字 | `status` が `ended` のときの終わりの札の文 |
| `questions` | 問いの配列 | 出した問い。まだ出していない論点はマップにだけ描く |
| `decisions` | 決定の配列 | 決まった問い。ID は問いと同じ |
| `rounds` | ラウンドの配列 | 経緯。ラウンドごとに出した問いと、解釈・訂正・新しい論点 |
| `summary` | 区画 | 終わったら。まとめの文と図（[summary.md](summary.md) の「`summary` の項目」） |

質問済みの数は `questions` の数、決定の数は `decisions` の数として組み立てが数える。ここに数を書かない。

### 区画（`intro` の要素と `map`）

| 項目 | 意味 |
|---|---|
| `id` | アンカー（`intro` のとき。省略可） |
| `eyebrow` | 小さな見出し（例 `MAP`） |
| `title` `lead` | 見出しと1〜2文 |
| `figs` | 図の断片のパスの配列。上から並べる。`map` では省き、組み立てに描かせる |
| `nodes` | `map` だけ。論点の札の配列 `[{id, name, after}]`。`name` は札に出す短い名前（16字まで。2行で切れる）。依存は問いの `after` を使い、まだ問いにしていない論点だけ `after` を書く。省くと全部の問いを題で並べる |
| `note` | 図の下の短い注（省略可） |
| `details` | 畳む欄 `[{summary, html}]`（省略可）。`html` は表などをそのまま入れる |

## 問い（`questions` の要素）

| 項目 | 意味 |
|---|---|
| `id` | `Q01` の形。変えない。アンカーは小文字（`#q01`） |
| `round` | 出したラウンド |
| `title` | 問い |
| `impact` | 影響（高・中・低） |
| `undo` | 後戻りのしやすさ（「後から変更可」「消した物は戻せない」など） |
| `after` | 依存する問いの ID の配列。前提の回答を受けてから出す |
| `multi` | 複数選べる問いなら `true`（チェックボックス） |
| `background` | 背景。分かっている現状と具体例。事実と仮定を分ける |
| `issue` | 争点。未決のことと、回答で変わる操作・表示・運用 |
| `options` | 選択肢 `[{key, name, text, pros, cons}]`。`key` は `A`・`B` か `1`・`2`。`name` は回答バーに出る短い名前、`text` は案の文 |
| `recommended` | 推奨の `key` の配列 |
| `why` | 推奨理由。開かなくても読める所に出る |
| `order` | 図の注文書（下の「図の注文書」）。2行まで |
| `fig` | 図の断片のパス（`fig/q01.svg` か `fig/q01.js`） |
| `fig_top` | 図が示す関係（図の上の左の札） |
| `fig_note` | 図の下の短い説明（省略可） |
| `steps` | ステップ再生のコマの説明の配列（図に `data-step` があるとき） |
| `details` | 背景の詳細・技術的な根拠（畳む。省略可） |
| `skip` | 見送るときの理由（省略可）。見送った問いは回答欄を出さない |

並びは組み立てが決める：回答待ち → 見送り → 決定（それぞれ配列の順）。

## 決定（`decisions` の要素）

| 項目 | 意味 |
|---|---|
| `id` | 問いの ID |
| `round` | 決まったラウンド |
| `pick` | 選んだ `key` の配列（回答）。札は「決定（A）」「決定（1・3）」になる |
| `line` | 何に決まったかを40字ほどの1行 |
| `adopted` | 採用した内容（全文） |
| `reason` | 理由。記録になければ「記録なし」 |
| `cost` | 引き受けた不便 |
| `rejected` | 却下した案（と再検討の条件） |
| `note` | 持ち主の備考と、その扱い（省略可） |
| `before` `after` | 前と後の図 `{fig, layers, at}`。同じ断片の別の層を指すと、同じ描き方・同じ尺度になる。`at` はコマの指定で、省くと最後のコマ。変えない決定は `before: null` |
| `cap_before` `cap_after` | 前と後を1行ずつ |
| `same` | 変えない決定なら `true`。図1枚と「前と後で変わらない」の文になる |
| `group` | まとめで決定を分けるまとまりの名前 |
| `wide` | 影響の大きい決定なら `true`（まとめで広く置く） |

## ラウンド（`rounds` の要素）

| 項目 | 意味 |
|---|---|
| `n` `version` `date` | ラウンドの番号・そのとき出したページの版・日付 |
| `asked` | そのラウンドで出した問いの ID |
| `notes` | 推奨と違う選択・採った解釈・訂正・備考から立てた論点など、1件1行 |

## 図の断片（`fig/`）

メインが書き、組み立てがページに差し込む。描き方は [figure.md](figure.md)。

- 数の図（横棒・積み上げ・時間の帯・タイル）は `.json` に型と数を書き、組み立て（`scripts/charts.mjs`）が SVG を描く。形は下の「数の図（`.json`）」。例は [../assets/fig.example.svg](../assets/fig.example.svg)（3案・下絵1回）。

- 1枚の図は1つの `<svg viewBox="…" role="img" aria-label="図の説明">…</svg>`。`.js` なら、parts.js の部品を使える関数の中身として書き、その文字列を `return` する。表などは `.html` でそのまま入れてよい。
- 色は土台の変数（`var(--ink)` など）で書く。CSS・回答欄・`<script>` は書かない（組み立てが差し込む）。
- **下絵は1回だけ描く。** 案で変わる所だけを `<g data-layer="A">` で包む。`data-layer` の外が下絵で、いつも出る。`data-layer="A B"` は A でも B でも出る。
- 問いの図は、初めは推奨の案（決定済みなら選んだ案）の層を出す。案を見るボタンと回答の選択で層が替わる。複数選択の問いは選んだ案の層を重ねて出すので、重ねても崩れない形に描く。
- 決定の前と後（`before` `after`）は、同じ断片の層を `layers` で指す。選択肢に無い名前の層（例 `N`＝今）を前のために描いてよい。
- ステップ再生は `<g data-frame="2">`（そのコマだけ出る）か `<g data-step="2">`（そのコマから出る。前のコマでは薄く出る）。コマの説明は問いの `steps` に、コマと同じ数だけ書く。
- 断片の中の `id`（矢じりの `<marker>` など）は、組み立てが同じ断片を2回置くときに頭を付けて分ける。
- **依存マップを手で描くとき（`map.figs`）は、札の形と位置だけを描く。** 1つの論点を `<a data-q="Q01">` で包み、中の枠に `data-tag`、状態を書く文字に `data-state` を付ける（`<text data-state …>Q01</text>`）。組み立てが page.json から状態を決め、文字を「Q01 · 決定（A）」「今回」「回答待ち」「見送り」「後で」に書き換え、色（決定＝ok・今回と回答待ち＝accent・見送りと後で＝mute の破線）と問いへのリンクを付ける。まだ問いに無い論点は「後で」になる。回答を入れて組み立て直すだけで札が変わるので、状態のためにマップを描き直さない。札の色・リンク・状態は aria-label に書かない。

## 数の図（`fig/qNN.json`）

モデルは座標と SVG を書かず、型・数・札・層だけを書く。文字の大きさ・色・層の印は手で描く図と同じ決まりで組み立てが付ける。札が棒に収まらない・右にはみ出すときは、組み立てが項目の場所を示して止まる。

| 項目 | 意味 |
|---|---|
| `type` | `bars`（横棒。積み上げ・時間の帯も）か `tiles`（タイルの並び） |
| `width` | 520（問いの図）か 1000（区画・まとめ）。省くと 520 |
| `title` `label` | 図の上の小さな見出し（尺度を書く）と、図の説明（aria-label。必須） |
| `max` `unit` `ticks` | bars の尺度の最大・単位・目盛りの数の配列 |
| `rows` | 行の配列。bars は `{label, segs, after, note, layers}`、tiles は `{label, items}` |
| `segs` | 棒の区切り `[{v, tone, text, from}]`。左から積む。`from` を書くとその位置から描く（時間の帯）。`text` は棒の中の札 |
| `after` `note` | 棒の右の札と、行の下の注 |
| `layers` | 案ごとに足す物 `{"A": {segs, after, note}}`。行の外の部分が下絵で、いつも出る |
| `marks` | 縦の破線 `[{v, text, layer}]`（合格の線など） |
| `items` `keys` | tiles のタイル。文字か `{text, swap: {"A B": "なし"}}`（その案では文字を差し替える）。swap を使うときは層の名前の配列 `keys` が要る |
| `count` | tiles の右の数 `{label, values: {"N C": "19枚", "A": "13枚"}}` |
| `legend` `foot` | 色の札 `[{tone, text}]` と、図の下の注 |
| `tone` | `base`（灰の面）・`accent`（濃い強調）・`soft`（薄い強調。既定）・`est`（破線。推定）・`q`（要確認）・`ok`（よい）・`mute`（消える物） |

例（3案で変わる費用の棒）:

```json
{"type": "bars", "title": "検証にかかる費用（0〜15ドル）", "max": 15, "unit": "ドル", "ticks": [0, 5, 10, 15],
 "rows": [
  {"label": "比べる相手", "segs": [{"v": 14.93, "tone": "base", "text": "前の第1ラウンド 14.93ドル（実測）"}]},
  {"label": "この検証", "layers": {
    "A": {"segs": [{"v": 3}, {"v": 2, "tone": "est"}], "after": "約3〜5ドル（推定）"},
    "B": {"segs": [{"v": 0}], "after": "追加 0ドル"}}}],
 "label": "比べる相手は14.93ドル。A は約3〜5ドル、B は追加0ドル。"}
```

## 図の注文書（`order`）

メインが問いごとに、図を描く前に書く。選んだ表現を短く書き出すことで、考える量を減らし、同じラウンドで図の型が偏っていないかを見られる。
問いの `order` に、次の4つを2行までで書く（組み立てが3行以上を止める）。

```
差：<選ぶと変わる物。同じ例・同じ尺度で見せる差>／表現：<表現の型（場面の絵・実物の画面・たとえ話・数のチャート・ステップ再生など）>
主役：<最初に目が行く物>／層：<案ごとに変わる所（A＝…・B＝…）。コマがあればコマの数と中身>
```

- 表現は visual-design.md の表から選ぶ。候補を2〜3個考えてから1つに決め、選んだものだけを書く。
- 層には下絵に入れない物だけを書く。下絵は「層」の外の全部（data.md の「図の断片」）。
- 描く物が決まるように、差と主役は、名前ではなく物で書く（「Q03 の違い」でなく「描くシートの枚数」）。

例（表現の型ごとに1つ）:

| 表現 | 注文書 |
|---|---|
| 場面の絵 | 差：PR を出してから直すまでに、人が手を止めて待つ回数／表現：場面の絵（机の前の人と画面の吹き出し）<br>主役：待つ人の砂時計／層：A＝待ち1回・B＝待ち3回・C＝待たずに次の作業へ |
| 実物の画面 | 差：同じ3件の出来事が届く通知の数とタイミング／表現：実物の画面（通知の札）<br>主役：画面の中の通知／層：A＝1通・B＝3通・C＝18時に1通（[fig.example.svg](../assets/fig.example.svg)） |
| 数のチャート | 差：ラウンドごとの文脈の大きさ（同じ尺度）／表現：数のチャート（前の線と後の線）<br>主役：後の線と20万の線／層：A・B・C で後の線の形が変わる |

# タスクのデータ（tasks.json）

議論が終わったら、まとめと同じフォルダに置く、タスクの正のデータ。エージェントはこれを読んで消化し、`scripts/task.mjs` で書き戻す（下の「書き方」）。
組み立てが summary.html の4章（依存の図・表・進み具合・チェックリスト・成果物）と `tasks.js` を書き、開いたままのまとめが数秒ごとに読み直す。
外のタスク管理・plan.md へは書き出さない。例は [../assets/tasks.example.json](../assets/tasks.example.json)（同じ架空の議論の6件）。

## ファイル全体

| 項目 | 意味 |
|---|---|
| `version` | 形の版（今は 1） |
| `discussion` | 議論のフォルダ（リポジトリからのパス） |
| `decided_in` | どの版の議論で決めたか |
| `skill_root` | 実装の対象が決まっていれば、そのパス（省略可） |
| `for_agent` | エージェントの進め方。ファイルの頭に置く（下の「進め方」）。文の配列 |
| `states` | state の値と、まとめに出す日本語 |
| `tasks` | タスクの配列。依存の順に並べる |
| `progress` | 進み具合の数え方の1文 |

## タスク（`tasks` の要素）

| 項目 | 書く人 | 意味 |
|---|---|---|
| `id` | 議論 | `T01` の形。変えない |
| `title` `short` | 議論 | 作業の名前と、図の札に出す短い名前 |
| `kind` | 議論 | 設計・実装・文書・配布・測定・検証・判定など |
| `owner` | 議論 | エージェント・持ち主など |
| `from` | 議論 | 元の決定の ID の配列。決定にない作業は `proposal` にする |
| `depends_on` | 議論 | 先に done になっているべきタスクの ID の配列 |
| `proposal` | 議論 | 議論で明示していない作業なら `true`。着手前に持ち主に確かめる |
| `steps` | 議論 | 手順。上から順に行う |
| `steps_done` | エージェント | 上から済んだ手順の数 |
| `files` | 議論 | 作る・直すファイル（分かる範囲）。無くても `[]` を書く |
| `done_when` | 議論 | 完了条件。見て確かめられる状態で書く |
| `how_to_check` | 議論 | 確かめ方 |
| `state` | エージェント | `todo`（まだ）・`doing`（作業中）・`done`（完了）・`blocked`（止まった。持ち主に聞く）・`dropped`（やめた。持ち主の判断） |
| `run_by` | エージェント | 作業中の担当（`main`・`sub-T07` など）。`task.mjs … doing --by` が書く（省略可） |
| `proof` | エージェント | 成果物（ファイルのパス・コミット・スクショのパス）の配列。まだ無ければ `[]` |
| `checked` | エージェント | 確かめた結果を1〜2行 |
| `note` | 両方 | 注。blocked にしたときは理由をここに書く |

組み立ては、知らない state・無い ID への `depends_on`・依存の輪を見つけたら知らせる。

## 書き方（`scripts/task.mjs`）

議論の後の tasks.json は、手で書かず `task.mjs` だけで書く。
ロックを取って読み・直し・書きをし、`build.mjs <議論のフォルダ> --tasks` で tasks.js を書き直す。2つの書き手（親とサブエージェント）が同時に書いても、両方の書き込みが残る。

| 操作 | コマンド（`task.mjs` は `node <このスキル>/scripts/task.mjs <議論のフォルダ>`） | だれが |
|---|---|---|
| 取る | `task.mjs T01 doing --by 担当の名前`（依存が done でないと断る。担当は `run_by`） | 親・サブエージェント |
| 手順を1つ済ませた | `task.mjs T01 step` | 親・サブエージェント |
| 完了 | `task.mjs T01 done --proof "パス" [--proof "パス"] --checked "確かめた結果"` | 親だけ（done_when を確かめてから） |
| 止める | `task.mjs T01 blocked --note "理由"` | 親・サブエージェント |
| やめる | `task.mjs T01 dropped --note "理由"`（持ち主が決めたときだけ。進み具合の分母から外れる） | 親 |
| 戻す | `task.mjs T01 todo` | 親 |
| 足す・直す | `task.mjs patch 差分.json`（tasks を id で足す・上書きし、ほかの項目は置き換える） | 親 |

どの操作にも `--note "注"` を付けられる。サブエージェントが書くのは、自分のタスクの doing と step だけ。

## 並べて進める

いま取れるタスク（依存がすべて done で todo）が2件以上あり、作業中のタスクとも互いにも `files` が重ならないものは、まとめの4章に「並べて動かせる」として出る（フォルダは前方一致で重なりとみる）。
既定では、親が番号の小さい順に1件ずつ進める。持ち主がサブエージェントで並べるよう明示したときだけ、この組から1件ずつサブエージェント（同じモデル）に渡す。`files` が重なるタスク・依存の残るタスク・持ち主が担当のタスクは渡さない。

## 進め方（`for_agent`）

tasks.json の頭に、エージェントが読む進め方を置く。例の7行をそのまま使い、議論ごとに変えるのは task.mjs のパスだけ。

1. `depends_on` がすべて done で state が todo のタスクが「いま取れる」タスク。依存の残るタスクは、前のタスクが done になるまで取らない。
2. いま取れるタスクは、番号の小さい順に親が1件ずつ進める。サブエージェントには、持ち主が明示したときだけ渡す。
3. tasks.json は task.mjs で書く。取ったら `doing --by 担当`、手順を1つ終えるたびに `step`。
4. `steps` を上から行う。決定（`from`）にないことはしない。
5. 決定と違うやり方が要りそうなら `blocked --note "理由"` で止め、持ち主に聞く。
6. `done_when` を `how_to_check` で確かめる。サブエージェントに渡したタスクも親が確かめる。
