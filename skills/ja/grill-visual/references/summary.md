# 議論のまとめ（summary.html）

議論が終わったあとに、決まった内容を「読む」ための1枚を作る。
議論ページ（index.html）は再開と回答のため、まとめは読んで作業に移るためのページにする。

まとめも組み立てで作る。章の枠・決定のカード・タスクの章・経緯の図は、
`scripts/build.mjs` が page.json と tasks.json から作る。モデルが書くのは、完成形・仕組みの図の断片と、タスクの中身だけ。
`summary` の文（頭の1〜2文・仮定・見直す条件）は、discussion.md の記録から写す。新しく書き起こさない。

## いつ作るか

- 未決ゼロ・ユーザーの「終わり」・上限到達のどれで終わっても、決定が1件以上あれば聞かずに作る。
- 決定が0件（資料作成だけ、まだ決定なし）なら作らない。
- 再開した議論がまた終わったら、同じ `summary.html` を組み立て直す。前の版から足した・変えた・取り下げた決定を `summary.changes` に書く（頭の「前の版からの変更」に出る）。

## 何を元にするか

- その議論の `discussion.md` と `page.json` を正とし、同じ会話で補う。版番号は page.json に合わせる。
- 他の議論・外部の資料は読まない。記録にない決定や理由を補わない（記録になければ「記録なし」と書く）。

## 読み手

未来の自分と、実装を任せるエージェント。自分には理由と却下案、エージェントにはタスクと完了条件が要る。
共有や公開のための整え直しはしない。

## 作る手順

1. page.json に `summary` を足す（項目は下の表）。決定のデータ（`decisions`）と経緯（`rounds`）は議論の間に書いた物をそのまま使う。
2. 完成形の図（`summary.big.fig`）と仕組みの図（`summary.mech[].fig`）の注文書を書き、メインが描く（[figure.md](figure.md)）。決定の図は議論ページの断片の層を使い回すので、描き直さない。
3. タスクを `tasks.json` に書く（形は [data.md](data.md) の「タスクのデータ」。例は [../assets/tasks.example.json](../assets/tasks.example.json)）。
4. `node <このスキル>/scripts/build.mjs <議論のフォルダ>` を流す。index.html・summary.html・tasks.js が書かれる。
5. `node <このスキル>/scripts/verify.mjs <議論のフォルダ>/summary.html` を1回。前と後の図・コマ・ダークを測る。

### `summary` の項目

| 項目 | 章 | 意味 |
|---|---|---|
| `title` `lead` | 0 | 決まった結果を1文、何が出来上がるかを1〜2文 |
| `changes` | 0 | 再開後に組み立て直すときだけ。前の版からの変更を1件1行 |
| `big` | 1 | 完成形の大きな図 `{title, lead, fig}`。決定をすべて反映した後の姿を1枚に描く |
| `mech_title` `mech` | 2 | 仕組みの図 `[{title, fig, full, steps}]`。2〜4枚で種類を変える。`full` は横いっぱい、`steps` はコマの説明 |
| `groups` | 3 | 決定のまとまりの並びと補足 `[{name, sub}]`。決定の `group` と同じ名前 |
| `tasks_title` | 4 | タスクの章の見出し |
| `assumptions` `revisit` | 5 | 仮定（外れたときの影響）と、見直す条件。1件1行 |
| `history_title` `end_notes` | 6 | 経緯の図の見出しと、「終わり」の札に載せる行 |
| `open` | 7 | 未決・保留の補足 `[{id, reason, needs, tasks}]`（省略可） |

## 章の順番と、だれが作るか

章の順番と枠は組み立てが固定する（`assets/frame/summary-parts.html`）。

| 章 | 中身 | 作る物 |
|---|---|---|
| 0 ヘッダー | 目的・版・決定数・未決数・タスク数・進み具合・目次・`index.html` と `discussion.md` へのリンク | 組み立て（文は `summary.title` `lead`） |
| 1 完成形の図 | 決定をすべて反映した後の姿を1枚。開いて最初の画面に入れる | メイン。決定は図の該当箇所に札 `<a class="chip" href="#d-q01">` で載せる。未決の札は `class="chip open"` |
| 2 仕組みの図 | 構成、流れ（ステップ再生）、状態の移り変わり、時間、具体例の表などから、決定を読み解くのに要るもの | メイン。同じ種類を重ねない。小さな議論では1枚でよい |
| 3 決定 | 決定ごとのカード：決まった物の図と見出し1行、前／後の切り替え、畳んだ理由・不便・却下・比べた案 | 組み立て（図は議論ページの断片の層、文は `decisions`） |
| 4 タスク | 進み具合・チェックリスト・依存の図・表・成果物 | 組み立て（tasks.json から。下の「タスク」） |
| 5 却下・仮定 | 仮定（外れたときの影響）と見直す条件。畳む | 組み立て（文は `summary.assumptions` `revisit`） |
| 6 経緯 | ラウンドごとに出した問い・決まった数・推奨と違う選択・解釈や訂正 | 組み立て（`rounds` と `decisions` から図を描く。推奨と違う選択は自動で載る） |
| 7 未決・保留 | 決まっていない問い・推奨・決めるのに要るもの・影響するタスク（あるときだけ） | 組み立て（決定の無い問いと `summary.open`） |

- 図を主役にする。文章は見出し1行と、畳んだ中に置く。
- 図は1枚で済ませず、題材に合わせて種類を変える。同じ型の小さな図を横に並べない（[visual-design.md](visual-design.md)）。
- 「次の一歩」の章は置かない。回答欄・回答バー・入力欄も置かない（読むだけのページ）。
- 決定・提案・仮定・未決は、色だけでなく文字でも区別する（組み立てが札に書く）。

## タスク（tasks.json）

決定から作業を導き、依存の順に並べて `tasks.json` に書く。

- タスクの正は tasks.json。まとめと同じフォルダに置く。外のタスク管理・plan.md へは書き出さない。
- 粒度は、1件が1つの成果物と1つの確かめ方で終わる大きさ。各タスクに依存（`depends_on`）・手順（`steps`）・完了条件・確かめ方・元の決定（`from`）を持たせる。
- 議論で明示されていない作業は `proposal: true`（図では破線と「提案」の札）。完了条件は見て確かめられる状態で書く。
- 頭に、エージェントの進め方（`for_agent`）を置く。例の7行を使い、議論ごとに変えるのは task.mjs のパスだけ。
- 自動の工程なので、ファイル・行まで特定するコード調査はしない。議論で出たファイル名は書いてよい。
- エージェントは `node <このスキル>/scripts/task.mjs <議論のフォルダ>` で tasks.json を書く（手で書かない）。書くたびに tasks.js が書き直され、開いたままのまとめが数秒で4章と頭の進み具合を描き直す（file:// で開いたときも動く）。いま取れて files が重ならないタスクは、4章に「並べて動かせる」として出る。持ち主がサブエージェントで並べると明示したときに使う（[data.md](data.md) の「並べて進める」）。

- discussion.md の「次に見る場所」に、`summary.html`（vN）を作ったことを1行書く。
- チャットでは summary.html のリンクと、決定数・未決数・タスク数を短く伝える。ページの全文は繰り返さない。
